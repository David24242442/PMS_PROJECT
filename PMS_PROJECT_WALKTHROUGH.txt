  sync, company-wide fresh goal generation, and reconciliation exports.
- Position 3 / Manager Flag (Line Manager):
  Authorized for Line Manager Console, Team Allocation, Subordinate Goal
  Appraisals, Scoring Reviews, and Leaderboards.
- Position 5 / Basic Role (Standard Employee):
  Restricted exclusively to /pms/goals (My SMART Goals) and /profile.
  Attempting to navigate to any other tab automatically redirects to /pms/goals.

DYNAMIC PERMISSIONS ATTRIBUTE:
The `users.permissions` database column stores a JSON array of allowed routes 
(e.g., `["/pms/goals", "/pms/appraisal", "/pms/review", "/hr/submissions"]`).
The router guard verifies route access against both `user.position_id` and the 
explicit `permissions` array.

     `position_id`, `is_manager`, `admin`, `permissions` (JSON), `remember_token`

2. `employees` (Master Onboarding Records from Server 17)
   - Primary key: `id` (bigint unsigned)
   - Core fields: `employeeid`, `emp_code`, `firstname`, `surname`, `othername`,
     `email`, `phoneno`, `department`, `job_title`, `status`, `joininglocation`,
     `line_manager_id`, `created_at`, `updated_at`
   - Purpose: Complete legal HR onboarding dossier.

3. `Monthly_Employees` / `monthly_employees` (Monthly Payroll Ingestion)
   - Primary key: `id` (bigint unsigned)
   - Core fields: `emp_id` (varchar 50, indexed), `employee_name`, `department`,
     `designation`, `location`, `status`, `cost_centre`, `date_of_joining`,
     `line_manager_id`, `month`, `year`
   - Purpose: Source of truth for active payroll employees.

4. `goals` (SMART Goals & Appraisal Dossiers)
   - Primary key: `id` (bigint unsigned)
   - Core fields: `user_id` (FK -> users.id), `employee_code`, `candidate_name`,
     `created_by` (FK -> users.id / manager), `manager_name`, `year`, `title`,
     `description` (JSON), `purposes` (JSON), `challenges` (JSON), `category`,
     `target`, `due_date`, `status` (assigned, submitted, completed),
     `smart_criteria` (JSON), `appraisal_data` (JSON), `attachment_path`
   - Purpose: Full performance evaluation cycle records.

5. `reviews` (Manager Periodic Reviews)
   - Primary key: `id` (bigint unsigned)
   - Core fields: `goal_id`, `user_id`, `manager_id`, `strengths`,
     `improvements`, `agreed_actions`, `rating`, `review_date`

6. Onboarding Child Tables (Linked to `employees.id` via `employee_id`):
   - `bank_socials`, `children`, `driverlicenses`, `education`
   - `emergency_contacts`, `guarantors`, `histories`, `irr_guarantees`
   - `irr_guar_witnesses`, `nominees`, `present_jobs`, `references`
   - `social_contacts`, `unions`, `uploads`, `wives`, `work_experiences`

DYNAMIC RESOLUTION ENGINE:
Because records originate across both the legacy Onboarding system (`employees`)
and monthly payroll Excel ingests (`Monthly_Employees`), controllers like
EmployeeMasterController and MonthlyEmployeeController use a dynamic union resolver:
1. Matches `Monthly_Employees.emp_id` against `employees.employeeid` or `emp_code`.
2. Resolves department and branch names through dynamic lookup dictionaries.
3. Automatically maps user portal accounts in `users` via `employee_code`.

--------------------------------------------------------------------------------
6.1 PAYROLL MASTER INGESTION (AUGUST 2026 PAYROLL INGESTION)
--------------------------------------------------------------------------------
- Responsible File: PMS_BACKEND_LARAVEL/app/Http/Controllers/MonthlyEmployeeController.php
- Source Dataset: c:\Users\USER\Workspaces\htdocs\PMS\AUGUST 2026 PAYROLL DATA.xlsx
- Process:
  1. The spreadsheet contains 5,920 employee records across 16 columns:
     EMP ID, EMPLOYEE NAME, DESIGNATION, DEPARTMENT, LOCATION, DATE OF JOINING,
     STATUS, COST CENTRE, etc.
  2. Executing GET or POST `/api/pms/clean-reingest`:
     - Truncates existing `Monthly_Employees` table.
     - Reads the master Excel spreadsheet using PhpSpreadsheet.
     - Sanitizes dates and employee codes.
     - Performs high-speed chunked batch insertions (1,000 records per chunk).
     - Result: Populates 5,920 records in seconds without memory exhaustion.

--------------------------------------------------------------------------------
6.2 LIVE CENTRAL SYNCHRONIZATION (SERVER 17 -> SERVER 20)
--------------------------------------------------------------------------------
- Responsible File: PMS_BACKEND_LARAVEL/app/Http/Controllers/EmployeeController.php -> syncFromCentral()
- Endpoint: POST or GET /api/sync-central-employees
- Frontend Trigger: "Sync Central Data" button on /onboarding
- Process:
  1. Opens a secure, read-only MySQL PDO connection to Central Server 17 (192.168.0.17).
  2. Queries Server 20 local database for `MAX(id)` on `employees`.
  3. Queries Server 17 for `WHERE id > localMaxId`.
  4. Copies new employees and corresponding child rows across 19 onboarding tables.
  5. Uses `insertOrIgnore` to guarantee zero duplicate keys or conflicts.
  6. Leaves Server 17 100% untouched and non-locked.

--------------------------------------------------------------------------------
6.3 AUTOMATED USER ACCOUNT & GOAL PROVISIONING
